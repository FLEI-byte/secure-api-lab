## Етап 3. Реалізація безпеки (Аутентифікація та Авторизація)

1-3. 
1. Створення Middleware для аутентифікації (`authMiddleware`) для того, щоб функція перевіряла, чи надав користувач коректні логін та пароль у заголовках запиту.
   
2. Створення Middleware для авторизації (`adminOnlyMiddleware`) для того, щоб функція перевіряла, чи має аутентифікований користувач роль 'admin'
   
3. Застосування Middleware до маршрутів було "вбудовано" перевірки у ланцюжок обробки запитів для кожного маршруту. Middleware передаються як аргументи до функцій `app.get()`, `app.post()` тощо, перед основним обробником.

![Крок 1-3](screenshots/01-1_git3-3.png)

![Крок 1-3](screenshots/01-2_git3-3.png)

4. Тестування захищених ендпоінтів

Перезапущено сервер (`node server.js`). Відкрито Postman і перевірено наступні сценарії:

**Сценарій 1 (Немає доступу):**

Зроблено `GET` запит на http://localhost:3000/documents без заголовків.

![Крок 4-1](screenshots/04-1_git3-3.png)

**Результат:** Статус 401 Unauthorized.

**Сценарій 2 (Доступ для user):**

Зроблено GET запит на http://localhost:3000/documents. Перехід на вкладку Headers. Додано два заголовки: X-Login зі значенням user1 та X-Password зі значенням password123.

![Крок 4-2](screenshots/04-2_git3-3.png)

**Результат:** Статус 200 OK та список документів.

**Сценарій 3 (Заборона доступу для user):**

Зроблено GET запит на http://localhost:3000/employees, використовуючи ті ж самі заголовки, що і в попередньому кроці (user1).

![Крок 4-3](screenshots/04-3_git3-3.png)

**Результат:** Статус 403 Forbidden.

**Сценарій 4 (Доступ для admin):**

Зроблено GET запит на http://localhost:3000/employees.

Змінено значення заголовків на: X-Login -> admin1, X-Password -> password123.
